# Luangwa Lion IPM

Integrated population model for lions in South Luangwa National Park, Zambia,
following the methods of Creel et al. (2024), *Conservation Science and
Practice*, "Changes in African lion demography and population growth with
increased protection".

The model has six components, estimated in a single joint likelihood:

| Component | Data | Estimates |
|---|---|---|
| Cormack–Jolly–Seber | `y[i,t]` capture histories | age-, sex- and protection-specific apparent survival, with a year random effect |
| Closed capture | `chc`, one history per year | annual population size, fit *outside* the IPM |
| Zero-inflated Poisson | `C[i]` first-year cubs per adult female | protection-specific fecundity, with a year random effect |
| Gaussian state-space | `Pop[t]`, sample composition | population size as a latent variable, and a growth rate per year |
| Movement | annual stratum transitions | dispersal rates between strata |
| Process error | the projection itself | real year-to-year fluctuation, separated from observation error |

## Layout

```
R/                      analysis scripts, run in numbered order
  00_paths.R            raw-input locations and a project-root guard
  01_capture_histories.R  Access DB -> capture histories, covariates, data bundles
  02_sighting_protection.R  overlay sightings on the park boundary
  03_closed_capture.R     per-year closed capture -> Pop[t]
  04_ipm.R                the integrated population model (JAGS)
models/                 model code: JAGS (.txt); an unused NIMBLE port (.R)
data-raw/               inputs, not tracked by git (see below)
data/                   derived data bundles, regenerated by the scripts
output/                 estimates and diagnostic plots
reports/                ipm_report.qmd, one parameterised source for both reports
archive/                superseded script versions and old data bundles
docs/                   JAGS code from the Creel et al. supplement
```

## Getting the raw data

Three inputs are not in the repository and must be put in place before
anything will run. Paths are declared in `R/00_paths.R`.

1. **`data-raw/Luangwa Database - 2024Nov22 - MDF.accdb`** — the sightings
   database (~108 MB). Too large for GitHub's 100 MB per-file limit, so it is
   shared out of band. Requires the 64-bit Microsoft Access Database Engine
   for `RODBC::odbcConnectAccess2007()` to open it.
2. **`data-raw/first-luangwa-paper/`** — capture histories, lion IDs with dates
   of birth, and litter records from Mweetwa et al.'s PLOS ONE paper. Tracked
   in the repository.
3. **`data-raw/wdpa/`** — World Database on Protected Areas extract for Zambia
   (polygons, WDPA + OECM). Download from
   [protectedplanet.net](https://www.protectedplanet.net). Not tracked;
   redownloadable.

## Running

Open `luangwa-lion-ipm.Rproj` so the working directory is the project root,
then:

```r
source("R/01_capture_histories.R")   # first pass: no protection file yet
source("R/02_sighting_protection.R") # writes data/sighting_protection.csv
source("R/01_capture_histories.R")   # second pass: builds area[i,t] for real
source("R/03_closed_capture.R")      # ~30 min, 16 models (cached after)
source("R/04_ipm.R")                 # the IPM itself (JAGS, ~2.5 h, chains in parallel)
```

The two passes of script 01 are deliberate. On the first run there is no
`data/sighting_protection.csv`, so `area[i,t]` falls back to a placeholder of
all 1s and the script says so loudly. Script 02 needs the sighting coordinates
that script 01 exports, and script 01 needs script 02's answer — hence the
loop. `sighting_protection.csv` is committed, so a fresh clone only needs one
pass unless the sightings change.

### Reports

`reports/ipm_report.qmd` is a single parameterised source that renders both
documents, selected by the tag on the IPM output it reads. From `reports/`:

```bash
quarto render ipm_report.qmd
```

```bash
quarto render ipm_report.qmd -P ipm_tag:_stoch --output ipm_report_stochastic.html
```

The report detects which components were switched on in the run it is reading
-- year random effects, process error -- and includes or drops the relevant
sections accordingly, so one source serves both the deterministic and the
stochastic fit.

## Analysis decisions worth knowing

These are set at the top of `R/01_capture_histories.R` and documented inline.

- **Occasions.** Four 2-month bins per year (May–Jun, Jul–Aug, Sep–Oct,
  Nov–Dec), 2008–2023, giving 64 occasions. Creel et al. used three bins
  (May–Oct); Luangwa's season runs later, and the fourth bin lifts retention
  from ~75% to ~90% of individual-months. `BIN_MONTHS` drives everything
  downstream, including the age matrix and the survival annualisation
  exponents.
- **Protection stratum.** Each of a lion's sightings in a year is classified
  inside or outside the park boundary, and the annual majority sets its
  stratum for every occasion in that year; ties are split evenly at random
  (`PROTECTION_RULE <- "annual"`). Taking the majority within each 2-month bin
  instead (`"occasion"`) preserves within-year movement, but in a bin with one
  or two sightings it is reading position off noise -- and that noise surfaces
  as dispersal: estimated inside-to-outside movement falls from 12.4% to 8.5%
  under the annual rule.
- **Interval lengths.** The four bins are not evenly spaced. They span 0.167,
  0.170, 0.167 and 0.496 of a year, the last carrying the Jan-Apr gap between
  field seasons. Survival is estimated annually and converted per interval as
  `ann^int.len`, rather than treating each interval as a quarter.
- **PLOS precedence.** Where Mweetwa et al.'s curated histories and the Access
  database disagree, the former wins — but scoped to the **lion-years actually
  listed in a source file**, not to every year of any lion appearing in any
  file. The 2013–2015 spreadsheets are partial working files (45–53 lions
  against 84–108 in Access), so the looser rule deletes real detections: 767
  individual-months lost versus 219, for the same 154 corrections gained.
- **Fecundity.** `litters.xlsx` reliably records the number and size of litters
  per pride-year; which female produced each litter is known for only 33 of 86
  litters. Litters are therefore allocated within their pride — named mothers
  first, the rest at random among the remaining adult females, one each.
  Counts and sizes are preserved exactly; only maternal identity is imputed.
  Set `FEC_IMPUTE_LITTERS <- FALSE` for the named-mothers-only version, which
  gives 0.31 cubs/female/yr against 1.18 from the pride totals.
- **Coordinates.** Sightings outside a South Luangwa bounding box, or recorded
  at a whole degree of latitude or longitude (minutes lost on data entry), are
  excluded from the overlay.
- **Unknown sex** is assigned at random under a fixed seed. The Creel et al.
  supplement notes this should eventually be a random variable inside the
  model.

## The closed-capture component, and why `Pop[t]` is incomplete

Mh closed capture is weakly identified in these data: `sigma` (individual
heterogeneity) and `N` trade off along a ridge, so the model can explain a
year in which each lion was seen fewer times either as few animals seen often
or as many animals mostly missed. Two things were tried.

**Occasion scale.** Creel et al.'s three 2-month bins give only four occasions
per year here. At that scale four of sixteen years failed to converge and the
series swung −63% then +103% between adjacent years. Closure is a within-year
assumption regardless of slicing, so `OCCASION_SCALE <- "monthly"` splits the
same months into eight occasions. That lifted convergence to 15/16, cut the
2017 credible interval from 306 to 62, and put 96% of observed
capture-frequency counts inside their predictive intervals.

**Pooling `sigma` across years** (`POOL_SIGMA`, kept but *not* recommended).
It looks better on every convergence metric — all 16 years at Rhat ≤ 1.016,
mean CV of N halved — but it achieves that by making N a near-deterministic
function of survey effort: the correlation between detections-per-known-lion
and N/known strengthens from −0.63 to −0.97. Precision without accuracy.

Neither fixes the underlying confound, and there is no effort covariate to
model it away with: `tblDaySheets` covers only Jan 2012–Apr 2013, and distinct
sighting-days correlates just 0.24 with detection intensity. So `Pop[t]` is
restricted to years meeting `MIN_DET_PER_LION` (2.5) that also converged and
did not hit the augmentation ceiling — **11 of 16 years**, following Creel et
al., who analysed density only over a window of constant monitoring intensity.
Excluded years enter the IPM as `NA` and simply contribute no likelihood term;
the survival and fecundity components still use all 16 years.

## Status

Done: capture histories, covariates, fecundity data, closed-capture model, and
the IPM (`R/04_ipm.R`, `models/lion_ipm_jags.txt`).

**Dispersal.** The Leslie projection moves survivors between strata each year
at rates estimated inside the IPM from the capture histories: 8.5% inside to
outside, 29.2% outside to inside, implying 77% of the population inside at
equilibrium against the ~80% observed. This matters: fitted without dispersal,
the stratum-specific quantities were unidentified, and adding composition data
to a no-dispersal projection distorted the vital rates instead. Stratum-specific
lambda comes out identical to total lambda, because dispersal holds composition
stationary -- so the report gives one growth rate, not two.

**Year random effects** on survival and fecundity, both on the *annual* scale
(`sigma.yr` 0.50, `sigma.fec.yr` 0.08). The scale is not a detail. Placed on
the per-interval scale the survival effect is unidentifiable and the posterior
just tracks whatever the prior allows -- 3.94 under U(0,5), 15.88 under
U(0,20). Per-interval survival sits close enough to 1 that the logit-scale
variance carries no information. On the annual scale, where survival is ~0.85,
it estimates cleanly at Rhat 1.00.

**Process error** in the projection (`sigma.proc` 0.090, a ~9% annual CV)
splits real fluctuation from imprecision in the closed-capture estimates.
Without it everything lands in `sigma.c`, which falls from 27.7 to 17.0 once
the two are separated -- about a third of what was being charged to observation
error is the population actually moving. It is also what gives lambda annual
structure: the deterministic projection returned a single growth rate repeated
for all 15 years, where the stochastic one ranges 0.91 to 1.12.

Of 1,266 monitored quantities all 1,240 free parameters converge (max Rhat
1.035). The remaining 26 are structurally constant, not unconverged: `gamma[1]`
is the fecundity reference level, and 25 `eps.proc` terms sit outside the years
the projection tracks.

**The IPM is fitted in JAGS, not NIMBLE.** The CJS component carries
590 x 64 = 37,760 discrete latent alive-states. JAGS has specialised machinery
for that; NIMBLE gives each node its own binary sampler and spends effectively
all its time there. Three NIMBLE formulations were tried and none was usable:
latent states ran ~70x slower than JAGS; marginalising with `dCJS_vs` from
nimbleEcology never got through `configureMCMC`, and neither did a custom
marginal CJS, because the variable-length declarations `dCJS` forces
(`y[i, f[i]:n.occasions]`) make NIMBLE graph analysis blow up.
`models/lion_ipm_nimble.R` is kept for reference only.

The IPM departs from `docs/R_JAGS_IPM_CODE.docx` in five places, each marked
in the model file and explained at the top of `R/04_ipm.R`. Two are
housekeeping (detection indexed by individual rather than duplicated across
occasions; fecundity as the analytic ZIP mean rather than an average over
hard-coded row ranges). Three change results and are worth a decision:

- **Recruitment.** Cubs are produced by adult females and split between the
  sexes. The published code derives female cubs from adult females and male
  cubs from adult *males* using the same rate, which doubles total
  recruitment given that `C[i]` counts cubs of both sexes per female.
- **Age mapping.** Survival is applied to the age classes it was estimated
  for — the CJS classes are two years wide, so cub survival covers ages 0→1
  *and* 1→2. The published code applies cub survival once and shifts every
  later class a year early.
- **Projection burn-in.** The Leslie projection runs 25 years before the first
  study year, with only overall scale free per stratum. Flat priors on 28
  starting abundances begin far from the stable age distribution (~41% of
  animals sit in the 6+ class), and a deterministic projection works that
  transient off slowly. Without it the fit showed a spurious decline from 599
  to 207 animals and pushed `sigma.c` to 73 against a bound of 100.

All three affect λ, so results are not directly comparable with the published Kafue
estimates. The annualisation exponents (`surv.exp`, `surv.exp.cub`) and the
fecundity region partition (`fec_bounds`) flow through from script 01 rather
than being hard-coded.

Four further components have no counterpart in the published code -- dispersal
between strata, year random effects, unequal interval lengths, and process
error. Each is switchable at the top of `R/04_ipm.R` (`USE_YEAR_RE_SURV`,
`USE_YEAR_RE_FEC`, `USE_PROCESS_ERROR`) or `R/01_capture_histories.R`
(`PROTECTION_RULE`), so a run can be reduced back toward the published
structure to see what any one of them is doing. `OUTPUT_TAG` names the run, and
every output file carries the tag, so alternative fits sit side by side in
`output/` instead of overwriting one another -- worth setting before starting
any run you want to keep, since `output/` is not tracked by git and therefore
does not change when you switch branches.
